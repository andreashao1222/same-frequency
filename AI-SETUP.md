# same frequency. — AI taste analysis

This version replaces the old hard-coded taste/recommendation logic with an AI-generated report.

## 1. Supabase

Run `supabase-social-migration.sql` in Supabase SQL Editor once. It adds the `ai_report` JSONB column.

## 2. Vercel environment variables

Add these to the Vercel project:

- `OPENAI_API_KEY` — your server-side OpenAI API key
- `OPENAI_MODEL` — optional; defaults to `gpt-5.6`

Keep `OPENAI_API_KEY` server-side. Do not put it in `NEXT_PUBLIC_*` variables or client code.

## 3. Redeploy

Push the changed files to GitHub, then let Vercel deploy the new commit. After deployment, submit a fresh profile to generate a new AI report.

## What changed

- Five selected artists are analyzed together instead of being mapped to a fixed genre table.
- AI generates the taste tags, `the read`, red flag, sonic-world fields, cultural matches, and musical opposite.
- Cultural matches always contain one artist, one album, one movie, and one book.
- Artist/album cards get Spotify search links generated by the site rather than hallucinated URLs.
- The generated report is stored in Supabase and reused when someone opens that profile.
- Matching now gives more weight to the AI-derived taste tags and less weight to exact artist overlap.
- Existing profiles without `ai_report` continue to use the old fallback logic.


## V8 behavior

AI analysis is now required for a profile report. The site no longer silently falls back to the old hard-coded indie/alternative recommendation system.

If `OPENAI_API_KEY` is missing or the API request fails, `/api/submit` returns a visible error instead of saving a fake fallback report.

Profiles created by older versions without `ai_report` are automatically regenerated the first time their report is opened.

Required Vercel environment variable:
- `OPENAI_API_KEY`

Optional:
- `OPENAI_MODEL` (defaults to `gpt-5.6`)
