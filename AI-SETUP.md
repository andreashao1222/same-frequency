# same frequency. — Doubao / 火山方舟 AI taste analysis

This version uses Doubao through Volcengine Ark's OpenAI-compatible Chat Completions API instead of the OpenAI API. The existing Supabase report storage and profile flow stay unchanged.

## 1. Supabase

No new SQL is required if you already ran `supabase-social-migration.sql` and the `ai_report` column exists.

## 2. Create a Volcengine Ark inference endpoint

In 火山方舟, create an online inference endpoint for the Doubao model you want to use, then create an API Key. The value needed by the app is the **Endpoint ID** (for example, an `ep-...` identifier), not a generic model display name.

Ark's OpenAI-compatible Chat Completions endpoint is:

`https://ark.cn-beijing.volces.com/api/v3/chat/completions`

## 3. Vercel environment variables

Add these to the Vercel project:

- `ARK_API_KEY` — your server-side Ark API key
- `ARK_MODEL` — your Ark inference endpoint ID

Keep `ARK_API_KEY` server-side. Do not put it in `NEXT_PUBLIC_*` variables or client code.

## 4. Redeploy

Push the changed files to GitHub, then let Vercel deploy the new commit. After deployment, submit a fresh profile to generate a new AI report.

## What changed

- OpenAI Responses API was replaced with Volcengine Ark's OpenAI-compatible Chat Completions API.
- The taste-analysis prompt is unchanged in substance, so the report still analyzes the five artists together rather than using the old hard-coded indie fallback.
- The app asks the model for JSON using `response_format: { type: "json_object" }` and validates/parses the returned object on the server.
- AI reports are still saved in Supabase and reused when profiles are opened.
- Artist/album links are still generated by the website rather than hallucinated by the model.
- If the Ark key, endpoint, or API request fails, the site shows a real error instead of silently generating a fake fallback report.

## Important

`ARK_MODEL` must be the **inference endpoint ID** you created in Ark. Do not paste your API key into `ARK_MODEL`.
